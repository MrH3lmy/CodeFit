# Gate 0 threat model and adversarial review

## Assets and trust boundaries

Protect learner SQLite/history, drafts/frozen submissions, evidence provenance, reserved challenge content, peer identity/consent and the host system. The renderer is treated as potentially compromised; locally bundled main/preload/Java code and the installed artifact are trusted. This is not protection against a malicious OS user replacing installed binaries, attaching a debugger or reading assets already shipped with CodeFit. It is not a sandbox for running arbitrary learner code.

| Threat | Implemented control | Verification / limit |
| --- | --- | --- |
| Renderer invokes arbitrary command/SQL/path | Frozen bridge has only `listDecks()` and `cancelRead()`. Main accepts no arguments, validates the owning WebContents/main frame/exact file URL; Java accepts only version 1 `decks.list` with UUID correlation. | Native bridge/unauthorized sender test, Java unknown method/extra field tests. No reflection dispatcher, HTTP listener or profile path input. |
| Node escape / hostile navigation | `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false`, `webSecurity:true`, no webviews; window opens, navigation, downloads and permissions denied. CSP denies network connections, frames, objects and inline scripts. Only files beneath bundled `dist/` may load. | Real renderer has no `require` or `process`; native preferences, denied fetch/window and offline namespace tested. Local OS sandbox configuration remains a platform prerequisite. |
| Reserved assets or source leak | DTO is an explicit id/name/description projection from a fresh sample DB. Renderer resource root excludes engine/runtime/filesystem. No challenge, evidence, attempt, profile or P2P operation exists. React renders descriptions as text. | Java output projection and strict response-schema tests. Packaged engine assets remain inspectable by the local OS user, as in JavaFX; this is not DRM. |
| Learner data corruption / cross-profile access | Separate JVM creates a new unpredictable temp directory, initializes only its own sample DB and then opens `mode=ro&immutable=1`. No supplied DB filename; no JavaFX startup/backfill. Dedicated Chromium data directory and single-instance lock. | Real SQLite write fails with code 8; DB bytes remain equal; real subprocess cwd learner sentinel remains unchanged; cleanup and URL restoration tested with the existing isolation extension. `immutable` must never be used for a live learner DB. |
| Malformed or unbounded IPC | Java: 1 KiB request, depth 4, strings 128, strict duplicate/unknown fields, exact integer version, newline framing. Main: 64 KiB response, fatal UTF-8, strict bounded Zod schema, matching pending UUID, one in-flight read. Response max 64 decks, name 256, description 2048. | Malformed/oversized/invalid UTF-8/version/correlation/private-field regressions. Failure closes the session; no automatic replay. Java-generated response duplication is not a separate authenticity boundary. |
| Process injection | Fixed bundled executable/classpath/working directory, `shell:false`; remove `JAVA_TOOL_OPTIONS`, `_JAVA_OPTIONS`, `JDK_JAVA_OPTIONS`, `CLASSPATH`. Startup requires Java 21 and the actual parent PID. | Missing runtime fails closed without PATH fallback; environment stripping and wrong-parent tests. Gate 0 never launches downloaded/peer code. |
| Hung/failed process | 15-second startup and per-read deadlines, bounded stderr count (16 KiB; discarded content), JVM heap `-Xmx128m`. Cancel/EOF permits cleanup, SIGTERM after 500 ms, SIGKILL after 2 s. Renderer/main loss stops child; Java monitors parent every 200 ms. | Timeout, ignored EOF/SIGTERM, forced Java/renderer/main crash tests. OS-level uninterruptible tasks/power loss cannot be guaranteed to terminate by a user-space deadline. Hard Java kill can leave only disposable sample files. |
| Stale result kills replacement / late spawn during quit | `EngineOwner` binds cleanup to the captured session identity, rechecks authorization after pending cleanup and rejects new work after shutdown intent. Main does not allow a repeated quit event to bypass cleanup. | Controlled old-result/new-session and shutdown/authorization interleaving regressions. React also suppresses responses from superseded read generations. |

Protocol stdout contains only ready/reply frames. Java emits generic diagnostic codes on stderr; Electron drains and bounds these without sending exception/path/content details to the renderer. UI errors identify the failure class and offer retry. Cancellation is **session termination for a disposable read**, not cancellation semantics for durable learner commands.

## Review findings and disposition

- Fixed: old cancelled request could close a newer Java session; authorization could expire while waiting for cleanup; repeated quit could bypass cleanup. Added explicit ownership and regression tests.
- Fixed before verification: initialization now occurs after installation of the Java cleanup hook, reducing interruption leftovers. URI-encoded SQLite filenames avoid special-character URL ambiguity. Cleanup deletes only this instance's known sample files.
- Fixed in Astra's final review: cleanup could restore the process-global database URL while initialization/read acquired a connection. Initialization, service reads and close now share a monitor and closed-state guard. A latch-controlled regression proves shutdown waits for the owned read; late initialization/reads cannot reach the restored URL.
- Verified: the real packaged app can load/query with no external network route and no system JDK dependency. Chromium sandbox remains enabled. The real Java subprocess exits after parent loss; the native test does not distinguish EOF handling from the watchdog, both of which provide cleanup paths.
- No learning policy duplication, new learner writes, exposure path, runner command or P2P access found in this narrow bridge.
- Deferred: native Windows/macOS lifecycle/signing/installer testing, a measured Tauri runtime comparison, writable profile ownership and durable mutation IPC. These limit ratification/cutover, not the demonstrated isolated read workflow.
- Hard-kill temp leftovers are documented; no unsafe global temp sweep was added. A writable learner process needs a separately reviewed recovery protocol before Gate 2 integration.

Astra high supplied the architecture and initial implementation/security analysis. Its implementation run hit a usage limit; continuation fixes and verification were completed by the coordinating agent. Astra resumed for final adversarial review, identified the database shutdown race, and verified its correction. No remaining blocker was found in the final reviewed changes, subject to passing the recorded tests and the explicit platform limits.
