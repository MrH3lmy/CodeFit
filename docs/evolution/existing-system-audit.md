## Trustworthy, subjective and derived fields

| Signal | What it can establish | What it cannot establish |
| --- | --- | --- |
| Existing persisted attempt/review ID | App recorded an event | Independent success, external authenticity |
| Workspace AC/ACX / finish reason | Learner-recorded external outcome | Machine-verified judge result (there is no authenticated judge adapter) |
| `CompletionOrigin.FRESH_ATTEMPT` | Fresh workspace recording for time/completion attribution | No hints, unseen problem or trusted grading |
| Local runner output / objective validator | Observed checks passed for exact artifact/configuration | Universal correctness, authorship, complete concurrency correctness |
| `SolvedWith`, difficulty, CONCEPT rating, mock score | Reported assistance/perception/performance | Independent verification; latest progress assistance does not describe every past attempt |
| Assessment `correct` | Stored assessment outcome | Historical hint use or grading provenance, which were not persisted |
| Raw review validation plus `hint_usage_recorded` | Explicit validator outcome and whether in-app hint observation exists | No outside assistance; default false in legacy rows is not observed independence |
| XP, streak, rank, readiness, card mastery | Derived engagement or scoped preparedness/retention under existing rules | General capability or proof of transfer |

Review/problem repositories omit timestamps on INSERT and SQLite supplies `CURRENT_TIMESTAMP`;
assessment attempts explicitly store Java `LocalDateTime`. Use persisted rows, not the returned
in-memory object's time, when adapting history. Legacy mixed writers and unknown completion origins
remain qualified. See [P2P time/provenance contracts](../p2p/protocol-v1.md) and preserve their semantics.

No current evidence should be upgraded merely because a new skill mapping is available. Unknown is
not failed, missing is not zero, and a problem being tagged concurrency says nothing about skill attainment.
