ORIGINAL-ONLY FIVE-BOOK CONTRACT v1 — DEVELOPER REVIEW ONLY

Boundary
--------
This is a future author-export format and a test-only offline validator, not a
production importer, curriculum publication, challenge catalog or approval system.
No private archive, PDF, source excerpt, proprietary example, private locator,
reviewer credential, answer key or real learner data is required or permitted.
Originality is an AUTHOR DECLARATION, not something a checksum/parser can prove.
Only independently authored structural metadata and short original author notes
belong here. Never copy book prose or examples into a note. If provenance is
unclear, omit the note and use ABSENT. Human copyright review remains a blocker.

The five book IDs are author-assigned canonical structural slots. The fixture
uses synthetic-book-one through synthetic-book-five; these are NOT book titles,
real coverage counts, author exports or mappings to the existing pilot. The
five book titles named by #298 are not independently enumerated by this fixture.
No private-source access is assumed.

Wire format and semantic rules
------------------------------
The JSON Schema defines exhaustive required field sets and local constraints.
The Java validator additionally enforces the relational/revision rules below.
Neither validator nor schema resolves a schema URL or any network resource.
UTF-8 only; maximum 2097152 bytes, depth 12, 131072 parsed values, strings 512
characters (IDs 128, notes 256), number token limit 8. Payload scalar values must
be strings: null, booleans, numbers, duplicate keys and trailing data are errors.
No type coercion, missing-field default, alias, unknown status or extra field.
Unknown schema versions require a separately reviewed validator, never fallback.

Exactly five unique books, 5..1024 units with at least one per book, 0..512 skills.
Each unit has at most 512 distinct skillIds. These caps accommodate the reported
five-book structural inventory without assuming that inventory is verified.
IDs are globally unique across books, units, skills and stages. Book/unit/skill
and revision IDs match [a-z][a-z0-9]*(?:[.-][a-z0-9]+)*. Stage IDs instead match
[A-Za-z][A-Za-z0-9]*(?:[.-][A-Za-z0-9]+)* to preserve legacy uppercase identities;
comparison is exact and case-sensitive, never a case-folded alias.
IDs are opaque, not filenames, suffix-derived
definition versions, source locations, URLs or implicit approval claims.
Every unit's skillIds must exactly equal the reverse skill.unitId association.
Every skill has one unit and the same book as that unit; each stage repeats
that exact book/unit/skill association. Each skill has exactly one each of
PREDICT, DEBUG, BUILD, DEFEND, including unavailable stages. Never drop a stage
to conceal an absence. A stage ID is opaque, globally unique and immutable for
its input revision; its kind is the separate stage field.
Prerequisites are at most 16 distinct catalog skill IDs; dangling external
references, self-edges and cycles fail the entire document. Future unresolved
external dependencies must be represented by explicitly unmapped skill metadata,
not silently dropped, invented as CodeFit definitions or treated as satisfied.

Coverage and categories
-----------------------
unit.coverage and stage.coverage are UNREPORTED or AUTHOR_REPORTED only.
They are author claims, not validated coverage or inferred completion counts.
unit.skillIds=[] explicitly records no skill mapping. Every skill.mappingStatus
is UNMAPPED. Exact SkillRef/GraphRef proposals are unsupported in v1.
brief.status distinguishes ABSENT, UNSUPPORTED and ORIGINAL_AUTHOR_DRAFT.
brief.text is empty for ABSENT/UNSUPPORTED; otherwise it is 1..256 ASCII
characters matching [A-Za-z0-9][A-Za-z0-9 ,;()'!?-]{0,255}. This deliberately
limited note channel excludes URL/path syntax, code, markup and source locators;
it is not a full mission brief format or a copyright detector. Do not encode
protected prompts, answers, hints or rubrics as notes. NO note text is exported.

Independent technical and pedagogical review are SEPARATE categories, bound to
the exact root revision. Each has a status and exhaustive transition history:
 UNREVIEWED   -> history [UNREVIEWED]
 REVIEW_PENDING -> history [UNREVIEWED, REVIEW_PENDING]
 UNSUPPORTED  -> history [UNREVIEWED, UNSUPPORTED]
All other transitions, histories, review decisions and reviewer identity/proof
fields are rejected. These are empty/pending decision slots, NOT authenticated
review results. Author assertions cannot grant independent review eligibility.
Actual approval/rejection/attestation exchange is out of scope; future review
work must reuse #253's independently trusted attestation boundary, bind decisions
to exact bytes, and never trust input-controlled credentials, signatures or
approval flags. This format does not create a rival reviewer trust model.

Stage consistency:
 ABSENT: UNREPORTED, ABSENT empty brief, both review categories UNREVIEWED.
 UNSUPPORTED: UNREPORTED, UNSUPPORTED empty brief, both categories UNSUPPORTED.
 UNREVIEWED: AUTHOR_REPORTED, original draft, both categories UNREVIEWED.
 REVIEW_PENDING: AUTHOR_REPORTED, original draft, at least one category pending,
                 other category UNREVIEWED or REVIEW_PENDING.
UNMAPPED, UNREVIEWED, UNSUPPORTED and REVIEW_PENDING never mean approved,
gradable, earned, mastered, released or challenge-authorized. Missing/unsupported
data is never converted to an empty-but-approved exercise.

permittedRelease must be METADATA_ONLY at root and every stage. No challenge or
content release is supported, regardless of category status. This permits only
local generation of the safe DTO for developer inspection; it is NOT authority
to publish an unreviewed content package or change a production release flag.

Exact revisions and atomic failure
----------------------------------
The developer supplies an external expected revision and SHA-256 of exact input
bytes. These must come from the intentionally selected local review candidate,
not a self-declared hash inside that candidate. Revisions and stage review
revisions must match; whitespace, ordering, notes and all metadata changes
invalidate the old byte pin. A matching pin proves identity only, not safety,
originality or approval. Every invocation still runs ALL structural checks.
Do not overwrite a revision's bytes or carry reviews to a changed hash. A new
candidate needs a new revision/pin and reset reviews; no approval store or
historical learner reference migration is introduced here.

Validation builds only local memory. Any failure returns error only, with no DTO,
manifest, files, catalog registration, SQLite initialization or learner mutation.
CLI exit 0 emits one complete JSON envelope {manifest,preview}; exit 1 emits
only {schema:"codefit-original-only-error/1",valid:false,category,code}.
Diagnostics contain fixed codes only, not values, exception causes, paths,
hashes or input fragments. Categories are FORMAT, ORIGINALITY, COVERAGE,
MAPPING, LINKS, STAGES, REVIEW, REVISION, RELEASE. Success means syntax and
revision validity only; category status remains explicit in the DTO.
Atomicity is validation-level: no output is prepared until ALL checks succeed.
A broken output pipe is not a transactional filesystem publisher. Consumers
must parse the entire envelope and verify its manifest before using artifacts.
The tool intentionally has no filesystem writer, path/HTTP input option,
runtime entry point, IPC command, database dependency or release action.

Public DTO and manifest allowlist
--------------------------------
DTO schema: codefit-original-only-public-preview/1 (NOT the existing 0.1 DTO).
Root: schema, revision, exposure=PUBLIC_PREVIEW, reviewStatus=UNREVIEWED,
permittedRelease=METADATA_ONLY, independentApprovals=0, books, units, skills;
releaseEligible, productionImportSupported, challengeExposure, graderAvailable,
xpEnabled, rewardsEnabled and masteryEnabled are always false.
Books: id.
Units: id, bookId, coverage, skillIds.
Skills: id, bookId, unitId, mappingStatus=UNMAPPED, prerequisites, stages.
Stages: id, stage, status, coverage, briefStatus, technicalStatus,
pedagogicalStatus. The parent skill supplies the validated book/unit links.
Never output notes, histories, review credentials, prompts, answers, rubrics,
private checkpoint locators, source text, evidence, XP or learner records.
Every input object is exhaustive, so protected preview fields are rejected,
not merely stripped. This DTO cannot round-trip to a challenge import.
Serialization: sorted object keys, original array order, compact UTF-8 JSON,
one LF. Manifest schema codefit-original-only-manifest/1 includes revision,
inputSha256, previewSha256 and permittedRelease=METADATA_ONLY. previewSha256
hashes the standalone serialized preview including LF, not the whole envelope.
The input hash is a local synthetic/export candidate pin, never a private ZIP
hash. The input file itself remains private when future original notes exist.

Coordination with coverage ledger #298 and Knowledge Atlas #302
-------------------------------------------------------------
The join boundary is books[].id -> units[].bookId -> skills[].unitId, pinned by
revision plus manifest.inputSha256; stage status and the separate coverage,
briefStatus, technicalStatus and pedagogicalStatus fields must not be collapsed.
The coverage ledger owns its source-attributed observedAt/source-version claims,
historical totals, nonadditive revision events and reconciliation; this input
does not accept those aggregates or claim to independently enumerate them.
Agree exact book IDs with the ledger in a future reviewed integration; never
join by display title, array position, a related-looking skill or "latest".

Crosswalk, not automatic publication:
 inventory -> explicit structural units only, not verified book completeness;
 preliminarily mapped -> author claim, never a resolved CodeFit SkillRef;
 first-pass/deep authored/mission blueprint -> UNKNOWN from this DTO; a short
   original note or a stage ID is not a full deep brief or a unique mission;
 review-approved -> unavailable; pending/unsupported are NOT approvals;
 locally previewable -> safe structural metadata only, no brief text;
 runtime import/graded/learner-validated -> unsupported, all flags false.
UNREPORTED means unknown, not zero coverage. AUTHOR_REPORTED is not a count or
an independently verified inventory. The reported per-book inventory baselines
and unknown distribution of preliminary mappings in #298 must remain separately
attributed ledger claims, never allocated from this synthetic fixture. Do not
sum replacement events as missions or infer a completion percentage from it.
No runtime, renderer, IPC or coverage-ledger files are modified by this contract.
